# Deploy Orbivex: Vercel frontend + Render backend

The React/Vite frontend runs on Vercel. The Express API runs on Render.
Supabase hosts the persistent database, authentication and Realtime services.
Both hosting services provide public HTTPS URLs, so users can access the app
from other devices and networks. No laptop server needs to remain running.

## 1. Prepare the repository and database

Use Node.js 24. The Git repository root is the folder containing this guide,
`frontend`, `backend` and `render.yaml` (locally `Orbivex-Edtech-platform-main`).
Push the reviewed application changes, including the new deployment files,
to your GitHub repository. Environment files and backups must stay private.

Use the same Supabase project for both services. For a **new, empty database**,
apply `supabase-setup.sql`, then the SQL files in `scripts/migrations` in filename
order, excluding `2026_07_10_remove_saas_billing.sql` (the existing migration
runner excludes it for fresh setup). Review SQL before execution. On an
existing database, apply only outstanding migrations; do not rerun the base
schema blindly. Include `2026_08_06_rls_hardening.sql` before public launch.
Verify RLS and any Realtime publications needed for notifications.
No database migrations run automatically during hosting builds.

## 2. Deploy the backend to Render

In Render, create a **Blueprint** from the repository and select `render.yaml`.
It configures:

| Setting | Value |
| --- | --- |
| Service | Node web service |
| Root directory | `backend` |
| Build command | `npm ci --omit=dev` |
| Start command | `npm start` |
| Health check | `/healthz` |
| Node version | `24` |

You can instead create a Web Service manually with these same settings.
Set environment variables in Render, using `backend/.env.example` as a reference:

| Variable | Value |
| --- | --- |
| `NODE_ENV` | `production` (already set by Blueprint) |
| `SUPABASE_URL` | Your Supabase project URL |
| `SUPABASE_KEY` | Public anon/publishable key |
| `SUPABASE_SERVICE_KEY` | Backend-only service-role/secret key |
| `ALLOWED_ORIGINS` | `https://YOUR_PROJECT.vercel.app` |

Choose the Vercel project name first; update `ALLOWED_ORIGINS` after Vercel
assigns the actual production domain if it differs. Use exact HTTPS origins,
comma-separated for multiple domains. No paths, wildcards or trailing slash
are needed. Add custom domains explicitly. Preview deployment domains are
not allowed automatically; add only previews you intend to connect to this API.
Render supplies `PORT`; the app listens on `0.0.0.0`.

Add `OPENROUTER_API_KEY` and/or `NVIDIA_API_KEY` to enable AI features.
Embeddings and tutor RAG additionally need `NVIDIA_API_KEY` and the database
vector migrations. Optional model/order/concurrency settings are in the root
`.env.example`. Add `RESEND_API_KEY` and a verified `EMAIL_FROM` for email
notifications, and your `SUPER_ADMIN_EMAIL` if using the admin email setting.

Save the public backend URL, for example `https://orbivex-api.onrender.com`.
Open `/healthz` on that URL: it must return `{"status":"ok",...}`.
`/api/health` also reports database and AI configuration; it can be slower.
A successful `/healthz` means the process is serving, not that database or AI
credentials have been verified.

The Blueprint starts with Render's free plan. Free services can sleep when
idle and the first request can be slow. Select an appropriate paid plan in
Render if you need consistent availability. Current details:
[Render free services](https://render.com/docs/free).

## 3. Deploy the frontend to Vercel

Import the same GitHub repository in Vercel and set:

| Setting | Value |
| --- | --- |
| Root directory | `frontend` |
| Framework | Vite |
| Node.js version | `24.x` |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Output directory | `dist` |

`frontend/vercel.json` provides build settings and the SPA fallback so opening
or refreshing `/login`, `/dashboard` and other React routes works. Static
assets, including the committed MediaPipe models and WASM generated by
`postinstall`, are included in `dist`.

Set these variables for Vercel's **Production** environment before deploying
(also set them for Preview if you want preview builds):

| Variable | Value |
| --- | --- |
| `VITE_API_URL` | `https://YOUR_SERVICE.onrender.com/api` |
| `VITE_SUPABASE_URL` | Same Supabase project URL as Render |
| `VITE_SUPABASE_KEY` | Same public anon/publishable key as Render |

The backend origin without `/api` also works; requests normalize to `/api`.
Production builds reject a missing API URL, localhost and plain HTTP.
Every `VITE_` variable becomes public browser code. Never put the Supabase
service-role key, AI provider keys or email keys in Vercel's frontend variables.
Changing Vercel variables requires a new build/deployment.

After deployment, set Render's `ALLOWED_ORIGINS` to the actual Vercel origin.
In Supabase Authentication URL Configuration, set the Site URL to your Vercel
URL and add any redirect URLs used by your auth flows. The current signup/login
flow goes through the backend; configure redirects before adding email/OAuth
flows. Use HTTPS for microphone/camera features and allow browser permissions.

## 4. Verify the public app

1. Open the Vercel URL from another device or network.
2. Open `/login` directly and refresh it; it should still load.
3. Sign up with a test account, log in, and confirm courses/dashboard data loads.
4. In browser Network tools, confirm API requests go to the Render URL under
   `/api`, with no localhost requests or CORS errors.
5. Verify tutor/assistant streaming, notifications and the features you use.
6. Verify camera/microphone proctoring and model/WASM requests for LSRW tests.
7. Confirm `/api/health` reports the database connected and required AI providers
   configured. A missing AI key can leave normal pages working but AI unavailable.

For local deployment checks, run `npm run test:deployment` in both `backend`
and `frontend`. Build the frontend with the three production `VITE_` values
set in your shell or a private `frontend/.env.production.local` file, then run
`npm run build`. Normal development still uses `npm run dev` in each folder;
the backend loads the existing root `.env` and the frontend uses its Vite proxy.

Reference: [Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite),
[Render Express deployment](https://render.com/docs/deploy-node-express-app),
[Render health checks](https://render.com/docs/health-checks).
